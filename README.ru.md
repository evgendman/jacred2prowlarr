# jacred2prowlarr

[English](README.md) | [Русский](README.ru.md)

**Адаптер JacRed v2 JSON → Torznab для Prowlarr, Sonarr и Radarr.**

Текущая версия: **2.2.10**

Адаптер преобразует данные раздач из JacRed в согласованный формат Torznab, который приложения *Arr могут надежнее распознавать и оценивать. Он решает две практические проблемы: названия релизов русскоязычных трекеров часто не соответствуют шаблонам распознавания Sonarr/Radarr, а проверка доступности индексатора может завершиться неудачно, если источник возвращает пустой результат для поискового запроса без названия.

## Зачем нужен адаптер

В названиях раздач русскоязычных трекеров часто смешаны локализованное и оригинальное названия, диапазон сезонов или серий, источник релиза, разрешение, видеокодек и информация об озвучке. Человеку это понятно, но непоследовательное именование мешает автоматически сопоставлять сериалы и фильмы и оценивать качество релиза.

Для русскоязычной медиатеки особенно важна озвучка. Название любимой студии или голосового перевода может присутствовать в метаданных раздачи либо только в ее исходном названии. При этом обычный результат индексатора не всегда предоставляет эти данные в форме, удобной для автоматического выбора.

Адаптер:

- преобразует **JSON API JacRed v2** в Torznab RSS/XML для Prowlarr;
- использует отдельные правила формирования названий фильмов и сериалов;
- строит нормализованное название для распознавания в *Arr, сохраняя исходное название раздачи JacRed;
- извлекает доступные обозначения озвучки и добавляет их в нормализованное название;
- для некоторых запросов сериалов находит подтвержденный русский альтернативный заголовок и дополняет результаты поиском по нему;
- отвечает локальными синтетическими элементами на распознанные проверки подключения с пустым поисковым запросом, не обращаясь при этом к JacRed;
- кэширует и исходные результаты источника, и готовые ответы Torznab, чтобы избежать повторных запросов при работе нескольких клиентов и постраничном просмотре;
- ограничивает частоту исходящих запросов к JacRed, снижая риск ограничения доступа со стороны источника.

Сам адаптер **не выбирает окончательную раздачу**. Он нормализует название и предоставляет метаданные, с которыми Sonarr/Radarr проще работать. Окончательный выбор выполняют настроенные в этих приложениях Quality Profiles и Custom Formats.

## Как проходит запрос

```text
Sonarr / Radarr
       |
       v
    Prowlarr
       |
       v
Адаптер JacRed TV + Movies
  127.0.0.1:9128/torznab
       |
       v
JacRed v2 JSON API (jac.red)
```

Для Prowlarr адаптер выглядит как Torznab-индексатор. Он слушает локальный порт и обращается к JacRed **только после поступления реального поискового запроса**; фонового опроса источника нет. Один работающий экземпляр адаптера может обслуживать Prowlarr и запросы от нескольких экземпляров Sonarr/Radarr, в том числе отдельных экземпляров для 1080p и 4K. Они используют общие кэши в памяти и один ограничитель исходящих запросов.

## Что возвращает адаптер

### Раздельное форматирование фильмов и сериалов

В адаптере две ветви форматирования:

- **Фильмы:** оригинальное название, год, формат/источник релиза, определенное разрешение/качество, распознанные обозначения озвучки, затем исходное название раздачи, если оно отличается от нормализованного.
- **Сериалы:** оригинальное название сериала, нормализованное обозначение сезона/серий, год, формат/источник релиза, разрешение/качество, обозначения озвучки, затем исходное название раздачи.

Примеры нормализации обозначений сериалов:

- релиз сезона `6 сезон (1-22 из 22)` → `S06E01-22`;
- диапазон серий `S11E01-10` → `S11E01-10`;
- сборник нескольких сезонов `1-11 сезоны` или `Seasons 1-11` → `S01-S11`.

Явное указание серий или диапазона серий имеет приоритет над общим указанием сезона. Благодаря этому сборник сезонов 1–11 не обозначается ошибочно только как одиннадцатый сезон.

### Пример: реальная многосезонная раздача «Секретных материалов»

Исходное название из JacRed:

```text
Секретные материалы (1-11 сезоны: 1-217 серии из 217) / The X-Files / 1993-2018 / ДБ (ТВ3), ПМ (ТВ3), СТ / HEVC / BDRip (1080p) | Дубляж
```

Нормализованное название, проверенное в Sonarr:

```text
X-Files S01-S11 (1993) BDRip 1080p | ТВ-3 *** Секретные материалы (1-11 сезоны: 1-217 серии из 217) / The X-Files / 1993-2018 / ДБ (ТВ3), ПМ (ТВ3), СТ / HEVC / BDRip (1080p) | Дубляж
```

В начале названия находятся предсказуемое имя сериала, диапазон сезонов, год, формат, качество и распознанная озвучка. Разделитель `***` сохраняет оригинальное название раздачи JacRed вместе с деталями источника, которые не обязательно нормализовать. Исходное название также передается в поле описания Torznab-элемента.

Для фильмов используется отдельная схема без сегмента сезона/серий.

### Озвучка и языки аудиодорожек

Если информация доступна, адаптер определяет обозначения озвучки в следующем порядке:

1. названия русскоязычных аудиодорожек в метаданных `ffprobe` от JacRed;
2. поле `info.voices` в данных JacRed;
3. распознавание поддерживаемых обозначений MVO в исходном названии раздачи.

Распознанная метка добавляется к нормализованному названию, например `| ТВ-3`. Доступные языки аудиодорожек также передаются в Torznab-метаданных. Эти признаки позволяют настраивать Custom Formats для приоритета любимой озвучки наряду с разрешением, источником, HDR и другими признаками релиза. Сами приоритеты и автоматический выбор настраиваются в Sonarr/Radarr.

### Качество, источник и метаданные протокола

При определении качества используется следующий приоритет:

1. размеры видеокадра из `ffprobe`, если они доступны;
2. поле JacRed `info.quality`;
3. явное обозначение разрешения в исходном названии раздачи.

Поэтому полезная информация о качестве сохраняется и тогда, когда в названии русской раздачи не указано разрешение. Если доступны маркеры HDR/Dolby Vision, 4K может быть обозначен как `2160p HDR`. При наличии данных ffprobe адаптер также передает разрешение в пикселях и видеокодек.

Дополнительно формируются корректный тип MIME `application/x-bittorrent` для torrent-enclosure, magnet URL и атрибут infohash. Даты JacRed в формате RFC3339/RFC3339Nano обрабатываются корректно. Некорректная или отсутствующая дата не заменяется текущей. Объединенные результаты по возможности дедуплицируются по infohash.

## Дополнительный поиск сериалов по русскому названию

Sonarr часто начинает поиск сериала с его оригинального или международного названия. На русских трекерах тот же сериал может быть проиндексирован по русскому названию, а в названии раздачи обе формы часто записаны через `/`.

Для запроса сериала не на кириллице адаптер проверяет, повторяются ли соответствующие пары названий в нескольких независимых результатах источника. Альтернативное название принимается только при наличии нескольких подтверждений и явного большинства у ведущего кандидата среди подходящих результатов. Затем адаптер:

1. отправляет в JacRed дополнительный запрос с найденным русским названием;
2. оставляет только те дополнительные результаты, которые также соответствуют каноническому названию сериала;
3. объединяет их с результатами исходного поиска;
4. удаляет дубликаты по infohash.

Например, в результатах по запросу Sonarr **`X Files`** в нескольких разных раздачах встретилась пара **`Секретные материалы / The X-Files`**. Адаптер распознал **`Секретные материалы`** как альтернативное русское название, выполнил дополнительный поиск по нему и добавил совпадающие раздачи X-Files. При этом нормализованное имя сериала остается **`X-Files`**: дополнительный поиск расширяет выдачу, но не подменяет название, используемое Sonarr.

Это осторожный поиск по подтвержденному альтернативному названию, а не слепой перевод и не безусловный второй запрос для каждого сериала.

## Поддержка Torznab и категории

Поддерживаются типы запросов:

- общий `search`;
- `tv-search`;
- `movie-search`.

Рекомендуемое имя индексатора в Prowlarr: **JacRed TV + Movies**

Адрес:

`http://127.0.0.1:9128/torznab`

Также поддерживаются пути `/torznab/api` и `/api`.

Поддерживаемые категории:

- **Сериалы:** родительская категория `5000`, включая подкатегорию аниме `5070`;
- **Фильмы:** родительская категория `2000` и категории источника `2010, 2020, 2030, 2040, 2045, 2050, 2060, 2070, 2080, 2090`.

В capabilities объявлены родительские категории Movies и TV и подкатегория Anime. В элементах выдачи указываются корректные родительские категории, сохраняются доступные категории источника и отмечается Anime, если это применимо. Если JacRed указывает для фильма только родительскую категорию, адаптер все равно может вернуть его в поиске по поддерживаемой подкатегории фильмов — при этом адаптер не выдумывает более конкретную категорию, которой источник не предоставлял.

## Локальные проверки подключения Prowlarr, Sonarr и Radarr

Проверка подключения индексатора — не обязательно реальный поиск по названию. Некоторые клиенты отправляют запрос с пустым параметром `q`. Если upstream-источник возвращает пустую выдачу, прямая настройка индексатора может провалить тест, хотя сам адрес доступен.

Для распознанной проверки подключения с пустым запросом адаптер возвращает небольшой **локальный синтетический тестовый ответ**, соответствующий клиенту и типу медиаданных:

- фильм для проверки типа movie/Radarr;
- сериал для проверки типа TV/Sonarr;
- оба типа для общего теста Prowlarr без фильтра категории;
- при необходимости учитываются запрошенные поддерживаемые категории.

Это тестовые элементы, а не настоящие раздачи JacRed. При формировании такого ответа запрос к JacRed не выполняется; дата публикации соответствует требованиям Torznab-клиентов.

Пустой запрос, содержащий идентификатор тайтла, год, сезон или серию, не считается проверкой подключения. Для таких структурированных запросов возвращается пустая выдача, а не вымышленное название; пустой запрос никогда не отправляется в JacRed.

## Двухуровневое кэширование в памяти

Адаптер использует два независимых кэша:

| Кэш | Время хранения по умолчанию | Максимум записей | Содержимое |
|---|---:|---:|---|
| Кэш исходных результатов | 180 с | 128 | Ответы JacRed по ключу: запрос, год, тип медиаданных |
| Кэш готовых ответов Torznab | 180 с | 512 | XML-ответы по параметрам, влияющим на конкретную выдачу |

Разделение особенно важно, когда один и тот же контент ищут несколько клиентов *Arr или несколько уровней качества:

- Разные страницы Torznab (например, `offset=0` и `offset=100`) требуют разных XML-ответов, но используют один набор сырых результатов JacRed.
- Локальная фильтрация по категории, сезону и серии не требует повторного получения тех же результатов от источника.
- Одновременные идентичные запросы объединяются на обоих уровнях кэширования.
- Разные API-ключи не создают отдельные записи для одинакового готового ответа.
- Ошибки, ответы с ограничением частоты и неполные ответы upstream не кэшируются как полноценные успешные результаты.

Кэши находятся в памяти и существуют только пока работает процесс службы; это не постоянное хранилище.

## Ограничение частоты запросов и обработка ошибок

Все исходящие запросы к JacRed проходят через общий для процесса ограничитель:

- запросы сериализуются, а не выполняются параллельно;
- по умолчанию между завершением одного исходящего запроса и следующим соблюдается пауза не менее **1000 мс**;
- HTTP 429 включает глобальный период ожидания; если JacRed передает `Retry-After`, адаптер учитывает его;
- если ожидание свободного слота превысит настроенный лимит очереди, адаптер быстро отвечает HTTP 503 с `Retry-After`, а не удерживает соединение до тайм-аута клиента;
- при общем поиске успешные результаты фильмов или сериалов сохраняются, если другая ветвь завершилась ошибкой; частичный ответ не кэшируется как полный успешный.

Переменные окружения и значения по умолчанию:

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `JACRED_MIN_INTERVAL_MS` | `1000` | Минимальная пауза между исходящими запросами |
| `JACRED_429_BACKOFF_SECONDS` | `60` | Пауза после HTTP 429, если нет пригодного `Retry-After` |
| `JACRED_MAX_QUEUE_WAIT_SECONDS` | `10` | Максимальное ожидание свободного слота |
| `JACRED_CACHE_TTL_SECONDS` | `180` | Время жизни кэша готовых ответов |
| `JACRED_CACHE_MAX_ENTRIES` | `512` | Максимум готовых ответов |
| `JACRED_SOURCE_CACHE_TTL_SECONDS` | `180` | Время жизни кэша сырых результатов |
| `JACRED_SOURCE_CACHE_MAX_ENTRIES` | `128` | Максимум наборов сырых результатов |
| `JACRED_LOG_REQUEST_PARAMS` | `0` | Диагностическое логирование параметров запроса; по умолчанию выключено |

Параметры можно задавать через environment overrides systemd-службы. Диагностическое логирование следует включать только на время поиска проблемы; значения параметров, похожих на учетные данные, исключаются из лога.

## Развертывание

Используется существующая systemd-служба:

`jacred-v2-adapter.service`

Путь установленного скрипта:

`/opt/jacred-v2-adapter/jacred_v2_adapter.py`

Адаптер слушает `127.0.0.1:9128`. Укажите приведенный выше адрес как Torznab-индексатор в Prowlarr на той же машине.

История реализации и оставшиеся задачи сквозной проверки описаны в [ROADMAP.md](ROADMAP.md).
