# Эндпоинты JacRed и цели проверки совместимости

Документ описывает API JacRed, важные для адаптера, и отдельно фиксирует факты о публичном сервере и целевой версии для локальных интеграционных тестов.

## Версии и базовая совместимость

### Публичный сервер по состоянию на 12 октября 2026 года

Прямой запрос к `https://jac.red/version` вернул:

- Версия: `3.15.0`
- Git SHA: `f43eeba8`
- Git-ветка: `HEAD`
- Время сборки: `2026-09-18 14:08:55 UTC`

Перечень маршрутов ниже привязан к соответствующему снимку исходников: [исходники JacRed на коммите `f43eeba8`](https://github.com/jacred-fdb/jacred/tree/f43eeba8). Наличие маршрута в коде не означает, что каждый маршрут отдельно проверен или доступен извне.

### Целевая версия для локальных интеграционных тестов

- Публичный источник, который сейчас использует адаптер: `https://jac.red`.
- Целевая версия для локальных интеграционных тестов адаптера: upstream-релиз/тег [`3.18.0-oss`](https://github.com/jacred-fdb/jacred/releases/tag/3.18.0-oss) — последний релиз upstream, проверенный 12 октября 2026 года.
- Репозиторий локального экземпляра и его настройки синхронизации/развёртывания: [evgendman/jacred-sync-node](https://github.com/evgendman/jacred-sync-node).

Перед тестированием необходимо сохранить фактический ответ локального `GET /version` — версию, Git SHA и время сборки. Нельзя утверждать, что тесты выполнены на `3.18.0-oss`, пока работающая версия не подтверждена. Если локальный экземпляр сообщает другую версию, следует зафиксировать и тестировать именно её.

Более новая целевая версия локальных испытаний не меняет публичный адрес источника в адаптере и сама по себе не доказывает, что публичный `jac.red` имеет те же маршруты или поведение.

## Поисковые API

### JSON API с совместимостью Jackett — API источника для адаптера

- `GET /api/v2.0/indexers/{status}/results`.
- Адрес по умолчанию в адаптере: `GET https://jac.red/api/v2.0/indexers/all/results`.
- `status=all` запускает поиск по объединённому индексу; имя конкретного трекера/индексатора ограничивает поиск.
- Обработчик принимает общие параметры поиска, включая `query`, `title`, `title_original`, `year`, параметры категории и `is_serial`; другие переданные параметры также доступны поисковому запросу.
- JSON-ответ содержит коллекцию `Results` верхнего уровня.
- `apikey` можно передать параметром запроса либо поддерживаемым HTTP-заголовком, если ключ настроен.

Именно этот JSON-маршрут использует адаптер. В версии 2.2.10 он отправляет `Accept: application/json` и собственный User-Agent проекта. Наблюдения о User-Agent и план совместимости описаны в [user-agent.md](user-agent.md).

### Получение списка индексаторов Jackett

- `GET /api/v2.0/indexers` — список агрегированного индексатора JacRed и настроенных трекеров в JSON-формате, совместимом с Jackett.

### Torznab XML

- `GET /torznab/api` — основной маршрут Torznab.
- `GET /api/v2.0/indexers/{indexer}/results/torznab/api` — альтернативный маршрут для совместимости с Jackett.
- `GET /api/v1/indexer/{indexer}/newznab` — альтернативный маршрут Newznab/Prowlarr.

Параметр `t` выбирает действие, например `caps`, `indexers`, `search`, `tvsearch` или `moviesearch`. Ответы этих маршрутов — Torznab XML, а не JSON, который непосредственно читает адаптер.

### API Prowlarr

- `GET /api/v1/indexer` — список индексаторов в формате Prowlarr.
- `GET /api/v1/indexer/{id}` — сведения об индексаторе; в изученной реализации агрегированный индексатор имеет `id=1`.
- `GET /api/v1/search` — поисковая лента Prowlarr с JSON-ответом.

### Собственный JSON API JacRed

- `GET /api/v1.0/torrents` — собственный поиск JacRed с фильтрами по названию/альтернативному названию, точному совпадению, типу, трекеру, озвучке, типу видео, году релиза, качеству и сезону.
- `GET /api/v1.0/trackers` — список названий трекеров.
- `GET /api/v1.0/qualitys` — поиск по вариантам качества.
- `GET /api/v1.0/conf` — проверка ключа API и совместимости.

Это самостоятельные интерфейсы. Само их наличие не означает, что адаптер их использует: URL исходного поиска адаптера остаётся `/api/v2.0/indexers/all/results`.

## Статус сервиса, статистика и синхронизация

### Сведения о сервисе

- `GET /health` — базовая проверка работоспособности процесса.
- `GET /version` — версия, Git SHA, ветка и время сборки.
- `GET /lastupdatedb` — время последнего обновления в индексе FileDB.
- `GET /health/background-jobs` — выполняющиеся фоновые задания по трекерам и сведения об их прогрессе.
- `GET /opensearch.xml` — описание поиска для браузеров с поддержкой OpenSearch.

### Статистика

- `GET /stats/torrents` — агрегированные количества раздач по трекерам.
- `GET /stats/tracks` — статистика модуля Tracks и метаданных аудиодорожек.
- `GET /stats/meta` — временные метки обновления статистики.

Доступность статистики управляется параметром `openstats`: наличие маршрута в исходниках не гарантирует открытый доступ к данным.

### API синхронизации

- `GET /sync/conf` — сообщает возможности протокола синхронизации.
- `GET /sync/fdb?key=...` — выдаёт подходящие бакеты/записи FileDB, если экспорт синхронизации разрешён.
- `GET /sync/fdb/torrents` — постраничный экспорт FileDB, который используют клиенты синхронизации JacRed.
- `GET /sync/torrents` — устаревший маршрут, направляющий клиентов на `/sync/fdb/torrents`.

Экспорт данных зависит от `opensync`. Ответ `/sync/conf` с версией протокола сам по себе не означает, что массовая выгрузка базы включена.

## Веб-интерфейс и административные маршруты

Веб-приложение обслуживается по путям `/`, `/stats`, `/jobs` и `/settings`.

В этом снимке исходников также есть семейства административных и диагностических маршрутов:

- `/api/v1.0/config` и подмаршруты — чтение, проверка, сравнение, разбор, преобразование, форматирование и сохранение конфигурации.
- `/cron/{slug}/{action}` и `/cron/maintenance/*` — запуск парсеров трекеров, обслуживание и управление фоновыми заданиями.
- `/jsondb/save` — запуск сохранения FileDB на диск.
- `/dev/*` — диагностика, обслуживание, миграция и экспорт данных Tracks.

Это не поисковые интерфейсы адаптера. Операции конфигурации, cron и dev могут изменять данные или раскрывать секреты; их не следует тестировать на публичном сервере. Для чувствительных операций код предусматривает доступ из локальной сети или отдельный `X-Dev-Key`/`devkey`. Защита поискового API ключом отделена от этих механизмов.

## Что известно о публичном сервере, а что нет

Во время диагностики 12 октября 2026 года публичный сервер сообщил версию `3.15.0` на `/version`. Главная страница и `/torznab/api?t=caps` в отдельных проверенных запросах возвращали HTTP 200, тогда как JSON-маршрут поиска адаптера ранее отдельно возвращал HTTP 403.

Эти наблюдения относятся к конкретным маршрутам. Успешный ответ `/version`, главной страницы или Torznab capabilities не подтверждает доступность `/api/v2.0/indexers/all/results`. Ответ 403 без явного срока не устанавливает причину, не доказывает блокировку всего домена по IP и не сообщает, когда доступ будет восстановлен. Не следует менять заголовки в цикле или многократно проверять публичный маршрут для обхода активного ограничения.

## План локальных интеграционных тестов

Для повторяемых интеграционных испытаний используем установленный локальный экземпляр JacRed из ссылки выше. Перед тестом сохраняем фактический ответ `/version` и фиксируем точную сборку.

1. Проверить JSON-маршрут со `status=all` и именем отдельного настроенного трекера; подтвердить корректный разбор JSON и наличие коллекции `Results`.
2. Проверить типичные запросы фильмов и сериалов, включая оригинальные/локализованные названия, год, сезон/эпизод, категории и пагинацию там, где они поддерживаются.
3. Проверить используемые адаптером поля, если они присутствуют: название релиза, magnet/infohash, качество, метаданные озвучки и языков, сведения `ffprobe` и дата обновления источника. Не считать необязательные метаданные гарантированными для каждой раздачи.
4. Проверить поведение при отсутствующем или неверном API-ключе, пустом запросе и запросах с дополнительными параметрами на локальном экземпляре.
5. Сравнить локальное поведение с публичной базовой версией `3.15.0`, зафиксировав отличия маршрутов, JSON-схемы или метаданных, а не предполагая полную совместимость.
6. Обработку HTTP 401/403/429, тайм-аутов, `Retry-After` и формирование заголовков проверять через локальный mock HTTP-сервер. Не создавать эти ошибки многократными запросами к публичному JacRed.

Результаты испытаний фиксировать в дорожной карте адаптера. До фактического запуска тестов `3.18.0-oss` является планируемой целевой версией локального тестирования, а не заявлением о завершённой совместимости.
